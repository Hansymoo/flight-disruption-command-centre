# Connection Rescue Operations Policy

## Purpose

This fictional policy defines how the operations team should respond
to passengers affected by disrupted inbound flights.

## Critical Cases

A connection should be treated as critical when the passenger has
already missed the connection or has a very high operational priority.

Recommended actions:

1. Identify the affected onward flight.
2. Check available alternative routing.
3. Prioritise time-sensitive rebooking.
4. Record the operational action taken.
5. Escalate unresolved cases to the duty operations team.

## High Priority Cases

High-priority connections require prompt review.

Recommended actions:

1. Monitor the inbound flight status.
2. Confirm remaining connection time.
3. Review alternative onward options.
4. Escalate if the connection buffer becomes negative.

## Medium Priority Cases

Medium-priority cases should remain under monitoring.

Recommended actions:

1. Continue monitoring the inbound flight.
2. Recalculate connection risk after significant updates.
3. Escalate if the status changes to AT_RISK or MISSED.

## Safe Cases

Safe connections do not currently require intervention.

The connection should continue to be monitored for new disruptions.

## Data Handling

This prototype uses fictional passenger and flight data only.

No real passenger personal information should be entered into
the application.
